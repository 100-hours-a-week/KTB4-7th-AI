# 세션 인계

이 프로젝트는 설계 문서가 위키·노션에 흩어져 있고 양이 많다. 새 세션마다 그걸 다시 훑으면
컨텍스트가 작업하기도 전에 소진된다. `docs/STATE.md` 하나만 읽고 이어갈 수 있게 유지한다.

## 새 세션을 시작할 때

1. `docs/STATE.md` 를 읽는다.
2. `git log --oneline -5` 와 `git status` 로 실제 상태를 확인한다.
3. **STATE.md와 실제가 다르면 실제를 믿는다.** STATE.md를 고치고 진행한다.
4. 위키를 다시 훑지 않는다. 특정 절이 필요하면 `doc-digger` 에이전트로 그 절만 가져온다.

## 인계 노트를 쓸 때

`docs/STATE.md` 를 아래 형태로 **덮어쓴다**. 이력을 쌓지 않는다 — 길어지면 안 읽힌다.

```markdown
# 작업 상태

마지막 갱신: YYYY-MM-DD
브랜치: feat/xxx

## 지금 어디
Task N (이름) 진행 중 / 완료

## 마지막으로 통과한 것
- `uv run pytest` — N passed
- (실제로 돌려본 curl 검증이 있으면 명령과 결과)

## 다음 한 걸음
(구체적으로. "챗봇 구현" 말고 "app/services/chat/tools.py 에 get_sales_summary 툴 추가")

## 미해결 결정
- (답을 기다리는 질문. 누구에게 물어야 하는지까지)

## 함정
- (이 프로젝트에서 실제로 시간을 날린 것들)
```

## 규칙

- **실제로 검증한 것만 "통과"로 적는다.** 테스트를 안 돌렸으면 안 돌렸다고 쓴다.
- 미해결 결정은 지우지 않는다 — 답이 오면 그때 지운다.
- 코드에서 읽을 수 있는 건 쓰지 않는다 (디렉토리 구조, 함수 시그니처). 파일을 읽으면 된다.
- 쓰는 건: **왜 그렇게 했는지**, **뭘 기다리는지**, **다음 한 걸음**.
- 짧게. 한 화면에 들어와야 한다.
