# 노션 계약 문서 조회

`docs/api정의서.md`·`docs/ERD정의서.md` 로컬 사본은 2026-10-13부로 삭제했다 — 노션 원본이
하루 안에도 바뀌는데 로컬 사본은 그때마다 수동으로 다시 복사해 넣어야 해서 계속
stale해지는 문제가 반복됐다. 이제 계약은 **항상 노션에서 그때그때 조회**한다.

## 절대 금지 — 쓰기 금지

이 두 페이지는 **읽기만** 한다. `notion-update-page`, `notion-create-pages`,
`notion-create-comment`, `notion-update-data-source` 등 **Notion MCP의 모든 쓰기 도구를
이 두 페이지(와 그 하위 블록)에 절대 호출하지 않는다.** API·ERD 정의서는 BE 담당 문서다 —
AI가 직접 고치거나 덧붙이지 않는다(2026-09-17 결정, 2026-10-13 재확인). 내용이 코드와
어긋나거나 오타·누락을 발견해도 **고치지 말고 BE에 알린다.** 지금 Notion 커넥터가 팀
워크스페이스에 쓰기 권한까지 연결돼 있을 수 있으므로, "도와주려고" 고치는 실수를 특히
조심한다.

## 고정 페이지

- API 정의서: https://app.notion.com/p/API-3d57f3faed48806bb27fd7f04ba53d5a
- ERD 정의서: https://app.notion.com/p/ERD-3d07f3faed48807aa1e0efe32abd2283

이 두 페이지는 팀 노션 워크스페이스(`박채원님의 워크스페이스`)에 있다. Claude의 Notion
커넥터가 이 워크스페이스로 연결돼 있어야 접근된다 — 개인 워크스페이스로 연결돼 있으면
`object_not_found`(404)가 난다. 404가 나면 먼저 사용자에게 Claude 설정 → 커넥터 →
Notion이 어느 워크스페이스로 연결돼 있는지 확인해달라고 요청한다(연결 해제 후 재연결 시
워크스페이스 선택기에서 팀 워크스페이스를 고르고, 이 두 페이지를 접근 허용 목록에
체크해야 한다).

## 사용 방법

1. **전체 문서를 메인 세션에서 직접 읽지 않는다** — 양이 많아(각 10만 자 이상) 컨텍스트가
   바로 찬다. `notion-fetch`로 직접 당겨도 토큰 초과로 파일에 저장되고 에러만 돌아온다.
2. 필요한 절(엔드포인트명, 테이블명 등)을 구체적으로 지정해서 `doc-digger` 서브에이전트에게
   발췌를 요청한다. 위 두 URL을 프롬프트에 그대로 전달한다.
3. 발췌는 원문 그대로 받는다. 요약해서 받지 않는다 — 금액/비율처럼 숫자가 정확해야 하는
   내용이 많다.
4. 노션 쪽 MCP 도구(`notion-fetch`, `notion-search`)가 메인 세션에 이미 로드돼 있고 찾는
   절이 작아서 확실히 안전하면, `doc-digger` 대신 메인 세션에서 `notion-search`로 먼저
   좁혀서 조회해도 된다 — 단 `notion-fetch`로 페이지 전체를 당기는 건 피한다(토큰 초과).

## 주의

- 발췌한 내용은 **그 세션에서만** 쓴다. 로컬 파일로 다시 저장해두지 않는다(다시
  stale해지는 문제로 돌아간다).
- 코드와 노션 내용이 어긋나면, 코드를 노션 기준으로 고치기 전에 **BE에 먼저 확인**한다
  (AGENTS.md "담당 경계" 참고 — API/ERD 정의서는 BE 담당 문서다. AI가 직접 고치지 않는다).
- 페이지 제목·ID가 바뀌었거나 404가 나는데 워크스페이스는 맞다면, `notion-search`로
  제목("API", "ERD")을 검색해서 새 URL을 찾고 이 스킬 파일을 갱신한다.
